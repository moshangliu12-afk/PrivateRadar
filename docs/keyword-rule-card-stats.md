# 关键词规则卡片统计

基线为 `98a2f16e7e3c5f1af267fad1249a5a72f5e11de9`。本轮只在现有规则列表读取中加入批量聚合，并在原规则卡片展示统计，不增加接口、表、缓存、后台任务或自动历史匹配。

统计直接投影现有持久有效结果：真实来源使用 `keyword_hits`，无附件旧消息使用 `keyword_rescan_coverage` 中仍有效且未被真实来源命中替代的记录。与现有列表采用相同排除条件。全部未归档规则在同一条只读 SQL 中聚合，再连接关键词；不会逐卡查询，也不受最近命中列表的 100 条上限影响。

历史命中数量为规则内 `COUNT(DISTINCT message_id)`。同一消息在多张真实来源卡片出现仍只计一条，正文相同但身份不同的消息分别计数。原最近命中列表和历史扫描汇总继续保留来源位置语义，没有修改它们。统计区域提示同一消息的多个来源只计一次。

最近发现时间为当前有效结果的 `MAX(matched_at)`，沿用既有命中建立或校准更新时写入的发现时间，不使用聊天发生时间、规则创建时间或任务表的扫描时间。无变化的幂等扫描不会重置该字段。界面直接调用关键词雷达已有 `timeLabel`，按既有系统本地时区和中文格式显示；无结果或无效时间为“暂无”。

手动历史扫描成功、失败或取消后的既有刷新回调会重新读取规则列表，因此卡片统计自动同步安全提交后的结果。正常导入后的下一次原有刷新或页面进入也读取相同来源。不引入订阅系统；编辑规则本身不自动全库扫描，明确重扫校准后，已删除的失效结果不再参与数量或最近发现时间。

停用组继续展示已有历史统计。组删除沿用当前归档语义：从活动卡片区域移除、不返回该组统计，原有折叠归档记录和既有命中保留。不新增物理删除操作或孤立统计记录。

查询不写数据库，不修改原规则、消息、来源事实、关系、Evidence、会话标签或 FTS。数据库迁移为零，匹配器、扫描器、扫描状态表、Evidence、Search、标签和三种 Export 实现保持不变。候选固定独立提交，完整备份和复制校验后交由用户只做本功能 A 至 J 桌面验收；不发布或进入下一功能。
