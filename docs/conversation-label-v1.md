# 会话显示名称 V1

用户可点击 Search、来源上下文、今日关注词、关键词命中或承诺卡片中的会话名称，设置、修改或清空自定义名称。清空会恢复上游名称；上游未提供名称时显示“未知会话”。来源名称不会随编辑而改变。

## 数据语义

- `sourceConversationName`：兼容复用 `conversations.name`，旧空串在读模型中映射为 `null`。没有新增或猜测来源事实。
- `userConversationLabel`：新增 `conversations.user_conversation_label TEXT`，旧数据默认 `NULL`；空白输入保存为 `NULL`。
- `displayConversationName`：由共享 `resolveDisplayConversationName` 按用户名称、来源名称、“未知会话”的顺序派生，不持久化。

消息的 `conversation_name` 和 Evidence occurrence 的 `source_conversation_name` 继续保留各自的来源事实。兼容读模型的 `conversationName` 不被用户名称替换；新增三层字段用于展示。当前会话来源名称与历史 occurrence 原始名称可能因后续来源补全而不同，两者不会被混写。

## 迁移与导入

沿用初始化器已有的按列检测迁移机制。在写锁内再次确认后只添加一个可空列，不重建表或 FTS，不改变原有批量导入结构版本、会话 ID、消息和 Evidence 关系，不创建新数据库。标签写入使用当前主进程已打开的数据库。

导入器的会话 upsert 只更新来源名称，不写用户名称。对同一来源的已有消息补全名称时保留原会话 ID，避免名称补全导致标签脱离。会话身份继续使用原有 ID，不按显示名称合并会话，也不把标签复制到其他 ID。

若同一个既有未知会话在本次补全中对应多个冲突来源身份，不猜选其中一个覆盖全局来源名称；各消息及来源记录仍保留各自事实。Evidence 中当前来源名称与历史原始记录不同的场合，会额外标明原始记录名称。

## 显示与刷新

各产品表面使用同一个名称组件和解析器。列表 API、Search、今日关注词、Keyword、Topic / Daily Evidence 及承诺读模型提供派生名称；原始字段仍可区分。保存后全局名称映射立即更新已打开卡片，重启时从数据库读取。应用焦点恢复或既有导入状态变化时刷新映射。

名称匹配支持用户名称及原来源名称，但不把标签写进消息、FTS 或 AI 来源事实。改变标签不触发历史重扫、评分重算或证据归档。

本版不包含颜色、分类、多标签、批量操作、自动命名或会话合并。

## 桌面验收修复与展示点核对

会话名称旁常显小型铅笔，悬停和键盘焦点使用既有绿色反馈，焦点另有清晰轮廓。提示为“修改会话名称”；具备会话 ID 的“未知会话”同样可以编辑。

已核对所有现有会话名称主展示点，均通过 `ConversationName` 和共享 resolver 派生显示名称，没有新增页面各自的回落逻辑。

| 已有位置 | 实际展示入口 | 结论 |
| --- | --- | --- |
| Search / 问我的聊天 | 已验证结果、时间未验证结果 | 使用统一显示名称 |
| 相关聊天证据 / 上下文 | `MessageContextPanel` | 使用统一显示名称 |
| Today 具体来源 | 关注词卡片复用 `KeywordOccurrence`，展开依据使用 `EvidencePanel` | 使用统一显示名称 |
| Topic 具体来源 | 展开的 `TopicEvidencePanel` | 使用统一显示名称 |
| 承诺候选、已确认承诺及上下文 | 共用 `CommitmentOccurrence` | 使用统一显示名称 |
| Keyword 具体命中及上下文 | 共用 `KeywordOccurrence` | 使用统一显示名称 |
| 今日汇总、Topic 聚合卡片、统计卡片 | 原本没有具体会话名称 | 不适用，不新增群名 |

编辑框的“来源名称”、Evidence 的“来源”及“原始记录会话名称”是明确标注的来源事实说明，继续保留原始语义，不被用户标签替换。附件名称、关键词组名和 Collection 名称也不属于会话名称。

本次只调整编辑入口并补充渲染测试，不改变 schema、resolver 优先级、来源同步或数据存储路径。WorkBuddy 同源改名仍只更新来源名称；已有测试覆盖用户标签保留及清空后回落到最新来源名称。
