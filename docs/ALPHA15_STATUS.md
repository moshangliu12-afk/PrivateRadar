# PrivateRadar alpha.15 开发状态

截至 2026-09-27，开发暂停，状态为 **BLOCKED ON EXTERNAL DEPENDENCY**。正式冻结版本仍为 `0.2.0-alpha.14`，标签为 `v0.2.0-alpha.14`；alpha.15 未发布。

## 已完成

- 双附件批量会话、附件项和独立导入任务；支持部分成功、需关注状态、中断恢复与原子认领。
- 每附件保存原始 ZIP 证据及消息快照，校验 SHA-256，维持稳定的 `source_batch_id`、确定性的 `source_position` 和重复执行时的现有去重行为。
- WorkBuddy 批量工具在创建会话前校验两个真实 ZIP 路径；路径缺失时不创建会话或附件项。项目内技能规则禁止扫描目录、按显示文件名拼路径或主动写 WorkBuddy 记忆。

## 真实验收

结果为 **PASS_WITH_ISSUE**：同次两附件最终成功导入 3 + 4 条消息，形成 1 个成功会话、2 个附件项、2 套证据、2 个任务；消息与全文索引均新增 7 条。首次错误路径曾产生失败会话；后续路径预检已修复此类副作用。成功调用前曾通过列举 `chat-history` 找到带前缀文件，不能把该做法视为正式入口已打通。

## 唯一正式入口阻塞

WorkBuddy 内部持有当前卡片 `chipId` 与复制后的真实 `zipPath`／`filePath`，但当前 Agent／Skill 上下文未正式透传真实 ZIP 路径。PrivateRadar Connector 不能独立从卡片标识取得该路径。

禁止通过列举 `chat-history`、搜索相似或最新文件、按时间猜测、或用显示文件名拼接路径绕过：这些做法不能证明路径属于当前卡片，可能误用历史附件或串批。也禁止直接修改第三方 `app.asar`：安装包更新、完整性及版本差异缺少可维护的部署与回滚保障。

## 恢复开发条件

WorkBuddy 提供可维护的 **当前附件路径透传**，或正式的 **`chipId` → 当前附件真实 `filePath` 解析接口**。在该条件满足前，不继续真实双卡片复测或发布 alpha.15。
